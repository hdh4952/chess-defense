# 백로그 — 요청됐으나 아직 착수하지 않은 작업

**기준** 커밋 `9ca758b` (v1.13 + 회귀 신호 9종) · **작성일** 2026-08-17

이 문서는 **사용자가 요청했지만 아직 구현하지 않은 것**만 담는다. 이미 구현된 것은
`game-design.md`가, 진행 방법은 `implementation-plan.md`가 담당한다. 항목이 착수되면
여기서 지우고 그쪽으로 옮긴다 — 두 곳에 같은 내용이 남으면 어느 쪽이 최신인지 알 수 없다.

우선순위는 매기지 않았다. 사용자가 정할 몫이다.

**B2(자원 압박) 1단계가 들어갔다** — 플레이테스트 후 계수 조정 또는 다음 레버 판단이 남았다.

**★ v1.21에서 보드가 3D가 됐다**(`game-design.md` §8.2). 아래 B3(그래픽 폴리시)와는 별개의
작업이고, 그 항목이 남긴 미결에는 영향이 없다. 3D 전환이 새로 만든 미결은 하나다 —
**스킨 아트가 2D라 기본 기물(입체)과 스킨 기물(눕힌 판)이 한 판에 섞인다**(§8.5).

## ~~B1. 적 유형 추가 (5종)~~ ✅ **완료** (v1.14 · 커밋 `d797f98` · `2b30d0c` · `a54bea9`)

다섯 종이 전부 들어갔다. 사용자 결정 둘로 착수 전 미결이 풀렸다:
**① 기존 3종을 재정의**(추가가 아니다 — 이름이 겹치는데 규칙이 다르면 둘이 동시에 붙는다)
**② 장갑형은 −2 고정이 아니라 문턱 방식**(합성 골드 중립성 보존).

| 유형 | 최종 규칙 | 해금 |
|---|---|---|
| 장갑형 | 원피해가 **문턱 3 미만이면 0**, 이상이면 전량 통과. 보스만 비율 0.875 | w6 |
| 고속형 | 속도 ×2.0 = **1.5초/칸** | w8 |
| 실드형 | **전방(낮은 랭크) 피해 무시** | w11 |
| 분열형 | 사망 시 인접 파일로 **2마리**(체력 절반, 재분열 없음) | w14 |
| 오라형 | 주변 2칸 적의 **유효 체력 +12**(중첩됨, 자기 제외) | w16 |

### 착수 중에 드러난 것 — 세 건은 규칙 설계였다

- **장갑형 문턱 3의 근거는 퀸 버프다.** T1 폰(2딜)은 혼자서 0이지만 퀸 라인 위에서
  2 × (1+1) = 4로 넘는다. 합성 T2 폰도 4다 → 해답이 **둘** 열려 있다. 하나만 열려 있으면
  "버프 강제"가 아니라 "폰 폐기"다.
- **실드형은 보스에 붙일 수 없다.** 실측으로 최소 승리 빌드의 w15 보스가 8/8 → **0/8**이 되고
  같은 골드를 높은 랭크로 전부 올려도 6/8이 최선이다 → 보스 처치 3/4 → 2/4 = 누수 −10 =
  시작 체력 전부. `swift`와 같은 논리로 `bossForbidden`에 넣었다. 그 결과 보스는 armored만
  달고 `bossTraitCountFromWave`가 휴면 상태가 됐으며, **보스가 v1.13보다 쉬워졌다.**
- **오라형은 흡수가 아니라 적립이어야 한다.** 흡수로 만들면 오라가 사는 동안 넣은 피해가
  전부 버려져 "오라를 먼저 죽여라" 한 갈래만 남는다. 적립이면 두 선택이 다 성립한다.

### ⚠️ 남은 귀결 — 밸런스 재조정 시 볼 것

- **실드형이 합성의 골드 중립성을 깬다** — 티어가 아니라 **칸 수** 때문이다(분산 15 대 합성 10).
  방향 규칙이라면 어떤 형태로든 피할 수 없다. N4에 전용 단언으로 기록했다.
- **"적 유형은 난이도 노브가 아니다(포화)"를 더 이상 근거로 쓸 수 없다.** 룩 1기/파일 누수가
  {17:4, 18:4, 19:5} → **{16:6, 17:7, 18:10, 19:10}**이 됐다.
- **분열형이 골드를 2배로 준다**(부모 + 자식 2×절반). 의도된 성질이지만 B2(자원 압박)와
  방향이 반대다.
- **보스 난이도가 내려갔다** — 실드형 금지로 w15·w20 보스가 armored만 단다.

## B2. 자원 압박 — 1단계 완료, 플레이테스트 대기 (v1.18 · 커밋 아래)

사용자 관찰이 두 번 있었다: "모든 구간에서 자금이 요구치를 앞선다"(설계 전), 그리고 실제
플레이 후 **"정가제 시절보다 어렵지만 전체적으로 너무 쉬움"**(v1.16 이후).

### 실측 — 잉여가 어디에 있는가

| 항목 | 값 |
|---|---|
| 총 수입 | **24,902G** = 시작 300 + **처치 18,402(74%)** + 클리어 보너스 6,200(25%) |
| 시점 편중 | 전반 w1~10 **7,226G** / 후반 w11~20 **17,376G** (70%가 후반) |
| 필요치 — 대칭 고정배치 | 17,900G → 잉여 **+39%** |
| 필요치 — 보스 파일 집중 | 8,500G → 잉여 **+193%** |
| 뽑기 가능 횟수 (정액 300G) | **83회** — 보드는 56칸 |

### 채택한 처방: 뽑기 비용 누진 (`gacha.costStep = 20`)

사용자 결정. **수입을 줄이는 대신 가격을 올린다.**

- 초반(w1~5)은 클리어 보너스 곡선으로 **일부러 열어 둔** 구간이라, 처치 보상 배수를 낮추면
  그 초반이 먼저 죽고 N3(w5 게이트 최소성)가 깨진다. 누진은 첫 뽑기를 300G로 두므로 안전하다.
- **사망 나선을 만들지 않는다** — 못하는 플레이어도 초반 뽑기는 같은 값에 한다.
- 실측: 뽑기 **83회 → 37회**(−55%). 초반 5회 총액은 1,500 → 1,700G(+13%)뿐인데 마지막 5회는
  초반 5회의 2.5배가 넘는다 — 잉여가 있는 곳만 겨눈다.
- `costStep`을 0으로 두면 정액 시절로 정확히 되돌아간다(롤백 경로를 신호가 못박는다).

### ⚠️ v1.20 난이도 선택은 B2가 아니다 — 축이 다르다

시작 화면에 이지/노멀/하드가 들어갔지만(20/30/40웨이브 · 적 마릿수·체력 ×1/×1.5/×2,
`game-design.md` §3.9) **B2가 겨누던 잉여를 건드리지 않는다.** 처치 보상이 적 체력이라 난이도를
올리면 수입도 같은 배수로 늘어난다 — 즉 난이도는 "적 총량" 축이고 B2는 "구매력" 축이다. 아래
판단은 그대로 남아 있고, 다만 **기준 난이도를 무엇으로 두고 재는지**를 앞으로는 명시해야
한다(실측은 전부 이지다).

⚠️ **웨이브 확장이 잉여 구조를 바꿔 놓았다** — 클리어 보너스가 w26에서 0에 닿으므로(500 −
20×(w−1)) 노멀·하드의 추가 웨이브 수입은 **전부 처치 보상**이다. B2 표의 "보너스 25%"는
이지에서만 참이고 하드에서는 1%다. 즉 **B2의 남은 노브 중 `clearBonusBase`/`Decay`는 긴
난이도에서 사실상 레버가 아니다.**

### ⚠️ 다음 단계 — 플레이테스트 후 판단

**아직 끝나지 않았다.** 자원만 조였으므로 사용자가 직접 해보고 여전히 쉬운지 확인해야 한다.
계수 후보: `costStep` 10(46회) / **20(37회, 현재)** / 30(32회) / 50(26회).

그리고 **자원 압박만으로 안 되면 다음 후보는 재배치다.** 지금 난이도는 골드보다 조작 지식에
몰려 있다 — 밸런스 감사의 "같은 8/8이 분산 6,000G 대 보스 파일 집중 1,500G(4배)"가 그것이고,
자동 플레이(뽑고 합치기만, 재배치 없음)는 **w2~w5에서 전패**한다. 즉 자원을 조이면 잘 두는
사람과 모르는 사람의 격차가 더 벌어진다. 사용자 지시로 그쪽은 **나중에** 본다.

### 남아 있는 다른 노브 (아직 안 건드림)

| 노브 | 현재 | 성격 |
|---|---|---|
| 처치 보상 배수 | **노브 없음**(암묵적 1.0) | 수입의 74%를 직접 건드리는 가장 큰 레버. 균등하게 깎아 초반이 위험하다 |
| `wave.clearBonusBase`/`Decay` | 500 / 20 (총 6,200G) | 25%뿐이고, 초반을 열려고 곡선으로 만든 값이라 되돌리면 w5가 위험하다 |
| `grant.everyWaves` / `weights` | 2(10회) / 비숍 .25 | 무상 지급. 비숍 비중이 잉여의 단일 최대 원인이었다(N1b) |
| `economy.sellRatio` | 0.5 | 뽑기 정가 비대칭 때문에 회수율이 실제로 83%다(300G에 뽑은 룩을 250G에 판다) |
| 분열형 골드 | 2배 지급 | v1.14가 만든 수입 증가. B2와 방향이 반대다 |

## ~~B3. 그래픽 폴리시 7종~~ ✅ **완료** (v1.15 · 커밋 `a78bf11` · `dbf6d24` · `2066fd3`)

일곱 항목 전부 들어갔다. 세 단계로 나눈 기준은 **닿는 계층**이었다.

| # | 항목 | 결과 |
|---|---|---|
| 1 | 피격 흰색 플래시 2프레임 | `enemyHit` 이벤트 + `render/enemyFx.ts`. `source-atop`으로 스프라이트 픽셀만 칠한다 |
| 2 | 히트스톱 30~50ms | 40ms · **룩 계열(pattern 'rook')만** · 최소 간격 250ms · 벽시계 감쇠 |
| 3 | 데미지 숫자 팝업 | 적별로 **합친다**. 막힌 피격은 숫자 대신 사선 고리 |
| 4 | 처치 파편 + 골드 HUD 비행 | 파편 5개(보스 14) · 골드는 2차 베지어 아치로 HUD까지 |
| 5 | ~~드래그 스냅 back-out~~ | **v1.17에서 되돌렸다** — 사용자 요청. 오버슈트가 기물이 흔들리는 것처럼 보였다 |
| 6 | 체력바 0.2초 보간 | 최대 체력 기준 고정 시간 선형 접근 |
| 7 | 레이저 잔광 + 폭 애니메이션 | crack·beam이 **세 겹**(잔광 넓어짐 ↔ 코어 얇아짐) |

### 착수 중 판단한 것

- **#2의 "나이트"는 성립하지 않았다.** v1.10에서 폭발을 잃고 공격 자체가 없어져(공격력 0)
  히트스톱을 걸 순간이 없다. 요청의 의도가 "무거운 타격"이라 판단해 이 게임에 남은 무거운
  타격(crack = 관통 균열 + 화면 진동)을 그대로 이어받게 했다 — 룩과 챈슬러다.
- **#3에 막힘 표식을 더했다** (요청 밖). v1.14의 장갑형(문턱)·실드형(전방 무시) 때문에
  "때렸는데 안 들어갔다"가 흔해졌는데, 화면이 말해 주지 않으면 폰이 왜 무력한지 알 수 없다.
  `enemyHit`을 **피해가 0이어도 발행**하고 숫자가 아니라 사선 고리로 그린다("0"을 띄우면
  데미지 0인 공격과 구분되지 않는다).
- **#4의 도착점은 밖에서 넣는다.** 렌더가 HUD 위치를 알면 계층이 뒤집힌다. 좌표가 없으면
  연출을 아예 만들지 않는다 — (0,0)으로 날리면 화면 왼쪽 위로 텍스트가 쏟아진다.
- **`prefers-reduced-motion`을 처음 도입했다.** 이 저장소에 그 처리가 하나도 없었다.
  원칙은 **정보는 끄지 않고 움직임만 끈다** — 데미지 숫자·체력바·막힘 표식은 유지하고,
  파편·골드 비행·스냅·잔광·히트스톱을 끈다.

### ⚠️ 남은 것

- **`enemyHit`은 이 게임 이벤트 중 유일하게 발행량이 다르다** — 한 프레임에 기물 수 ×
  사거리 안 적 수만큼 나온다. 소비하는 쪽(effects)이 적별로 합쳐 막고 있지만, 새 소비자가
  붙으면 그쪽도 같은 방어를 스스로 해야 한다.
- **파편 개수가 화면 부하를 정한다.** 후반 웨이브가 초당 수십 마리를 처치하므로 일반 적의
  5개가 상한이다. 테스트가 `toBeLessThanOrEqual(6)`으로 막고 있다.
- 연출의 **모양**은 테스트가 감시하지 않는다(눈으로 볼 몫이다). 테스트가 지키는 것은
  계층·수명·발행 규칙뿐이다 — 그 셋이 눈으로 못 보는데 조용히 망가지는 것들이다.
- ★ **#5는 실제로 되돌려졌다**(v1.17). 그것이 위 줄의 실례다 — 모양은 눈으로만 판단되고,
  이 경우 오버슈트가 "기물이 흔들린다"로 읽혔다. 되살릴 일이 있으면 원래 풀려던 문제
  ("드롭 즉시 감추면 어디에 놓였는지 눈으로 따라가지지 않는다")를 **움직이지 않는 표현**으로
  푸는 편이 낫다 — 착지 칸을 한 프레임 강조하는 식으로.
